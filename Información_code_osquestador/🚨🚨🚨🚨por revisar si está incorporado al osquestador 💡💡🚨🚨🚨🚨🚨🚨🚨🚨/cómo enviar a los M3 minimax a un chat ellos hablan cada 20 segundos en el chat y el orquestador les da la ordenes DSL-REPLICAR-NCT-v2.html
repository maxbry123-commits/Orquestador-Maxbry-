🔁 PASO 3 · Loop persistente por Mavis (m3-loops-mode skill)

El skill ya está registrado en mi memoria. El Mavis corre esto en su sandbox:

# /tmp/sandbox-tarea-{N}/loop.sh
#!/bin/bash
ID="A{N}"
SANDBOX="/tmp/sandbox-tarea-{N}"
REPO="{REPO_TARGET}"  # nct-hub | orch-auditor | ws-relay
DURATION_HOURS=18
POLL_SECONDS=20
BACKOFF_MAX=60
END_TS=$(($(date +%s) + DURATION_HOURS*3600))

BITACORA="$SANDBOX/bitacora.md"
HEARTBEAT="$SANDBOX/heartbeat.log"
touch $BITACORA $HEARTBEAT

log() { echo "[$(date -u +%Y-%m-%dT%H:%M:%SZ)] [$ID] [$1] $2" >> $BITACORA; }

log "INIT" "modo loops · ${DURATION_HOURS}h · poll ${POLL_SECONDS}s"

SLEEP=$POLL_SECONDS
LAST_HEAD=""

while [ $(date +%s) -lt $END_TS ]; do
  RESULT=$(git ls-remote git@github.com:maxbry123-commits/${REPO}.git 2>&1)
  HEAD=$(echo "$RESULT" | head -1 | awk '{print $1}')
  
  if [ -n "$HEAD" ] && [ "$HEAD" != "$LAST_HEAD" ]; then
    log "CHANGE" "$LAST_HEAD -> $HEAD"
    LAST_HEAD="$HEAD"
    # ↓↓↓ Acá el Mavis ejecuta su tarea ↓↓↓
  fi
  
  echo "[$(date -u +%Y-%m-%dT%H:%M:%SZ)] [$ID] [ALIVE]" >> $HEARTBEAT
  sleep $SLEEP
done

log "STOP" "completado"

Lanzar con nohup + disown para que sobreviva al cierre del turn:

nohup bash /tmp/sandbox-tarea-{N}/loop.sh > /dev/null 2>&1 &
disown

⚠️ ERRORES COMUNES (anti-alucinación)

  1. ❌ Misma key pública en 2 repos → GitHub rechaza. Cada key es ÚNICA por repo.
  2. ❌ Mavis usa HTTPS con PAT → No tiene token, falla 401. Usar SIEMPRE SSH.
  3. ❌ Mavis no tiene acceso a TAREAS-PENDIENTES → Las deploy keys son POR REPO. Espejar o usar Forma A (chat).
  4. ❌ Loop muere al cerrar turn → Usar nohup + & + disown.
  5. ❌ Mavis se duerme → El sleep 20 sin más no es idle. SIEMPRE hacer git pull antes de chequear.
  6. ❌ Mavis pisa trabajo de otro → Cada uno su sandbox /tmp/sandbox-tarea-{N}/, su branch feature/tarea-{N}.
  7. ❌ Subir SSH keys a GitHub → NUNCA. Son privadas, irian en ~/.ssh/ solamente.
