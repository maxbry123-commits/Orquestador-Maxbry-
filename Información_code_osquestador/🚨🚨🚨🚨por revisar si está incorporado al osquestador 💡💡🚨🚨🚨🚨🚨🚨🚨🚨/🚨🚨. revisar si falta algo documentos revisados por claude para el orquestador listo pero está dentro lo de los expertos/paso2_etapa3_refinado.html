🎯Resumen Ejecutivo

El Output Cognitive Fabric es el último filtro antes de entregar la respuesta al usuario. Tú propusiste 10 expertos. Esta versión refinada los implementa con:

  • Contratos I/O tipados (Pydantic) para cada experto
  • 10 checks binarios objetivos (cada uno PASS o FAIL con issues específicos)
  • Pipeline secuencial con reparación automática (1 retry antes de escalar)
  • Hallucination detection con sampling (借鉴 SelfCheckGPT)
  • Audit log hash-chained inmutable (借鉴 kbot-finance)
  • Final Judge con regla dura: TODOS los checks deben pasar
Regla dura del Output Fabric

El Orquestador solo entrega la respuesta si los 10 checks pasan. Si alguno falla irreparable, se escala al humano (no se entrega respuesta defectuosa).

🧠Los 10 Expertos del Output Fabric — Diseño Completo

Format Controller
Garantiza que el formato del output coincide con el OutputContract.
E-OUT-001

Input: (output: str, expected_format: Literal)

Output: CheckResult(status: PASS|FAIL, issues: list[str])

Tarea: Verifica que el formato (markdown, json, code, multi_file) coincide con el declarado en el OutputContract. Si es JSON, valida que sea parseable. Si es Markdown, valida sintaxis básica.

Completeness Checker
Verifica que TODOS los artefactos esperados están presentes.
E-OUT-002

Input: (delivered: list[Artifact], expected: list[str])

Output: CheckResult(status: PASS|FAIL, missing: list[str])

Tarea: Compara la lista de artefactos entregados contra los declarados en el OutputContract. Ningún artefacto puede estar vacío o faltar.

Evidence Checker
Verifica que cada claim tiene evidencia verificable.
E-OUT-003

Input: (output: str, sources: list[Source])

Output: CheckResult(status: PASS|FAIL, ungrounded_claims: list[str])

Tarea: Cada claim factual debe tener una source reference. Usa HHEM-style: NLI entre el claim y su fuente. Si un claim no tiene respaldo, se marca como ungrounded.

Goal Checker
Verifica que el output cumple el goal original del usuario.
E-OUT-004

Input: (output: str, original_goal: Goal)

Output: CheckResult(status: PASS|FAIL, coverage_score: float, missing_criteria: list[str])

Tarea: Compara los success_criteria del goal original contra el output. Calcula coverage_score (0-1). PASS si >= 0.85.

JSON Validator
Valida estructura JSON contra schema.
E-OUT-005

Input: (json_str: str, schema: JSONSchema)

Output: CheckResult(status: PASS|FAIL, schema_errors: list[str])

Tarea: Si el output es JSON, valida contra el JSON Schema del OutputContract usando jsonschema library. Cada campo debe estar presente y tener el tipo correcto.

Markdown Builder
Renderiza y valida Markdown.
E-OUT-006

Input: (md_str: str, audience: Literal)

Output: CheckResult(status: PASS|FAIL, syntax_errors: list[str], rendered: str)

Tarea: Verifica sintaxis Markdown válida. Adapta el nivel de detalle al audience (technical/executive/general). Renderiza a HTML si es necesario.

Report Builder
Estructura el reporte final con secciones canónicas.
E-OUT-007

Input: (raw_artifacts: list[Artifact], template: ReportTemplate)

Output: CheckResult(status: PASS|FAIL, report: StructuredReport)

Tarea: Organiza los artefactos en un reporte estructurado: Resumen Ejecutivo, Análisis, Conclusiones, Fuentes, Apéndices. Verifica que cada sección canónica esté presente.

Consistency Checker
Detecta contradicciones internas en el output.
E-OUT-008

Input: (output: str)

Output: CheckResult(status: PASS|FAIL, contradictions: list[tuple[str, str]])

Tarea: Usa DeBERTa-NLI para comparar cada par de párrafos/secciones. Detecta contradicciones (label=CONTRADICTION). PASS si 0 contradicciones o solo contradicciones triviales.

Hallucination Checker
Detecta fabricaciones del modelo.
E-OUT-009

Input: (output: str, original_query: str, sources: list[Source])

Output: CheckResult(status: PASS|FAIL, inconsistency_score: float, suspected_spans: list[str])

Tarea:借鉴 SelfCheckGPT: muestrea N=5 variantes de la misma respuesta. Mide inconsistencia entre variantes. Si >30% se contradicen → FAIL. Marca los spans sospechosos.

Final Judge
Decide aprobación final o escalación.
E-OUT-010

Input: (all_check_results: dict[str, CheckResult])

Output: FinalVerdict(approved: bool, reason: str, escalate_to: str | None)

Tarea: Revisa TODOS los resultados de los 9 checks anteriores. Regla dura: si CUALQUIER check dio FAIL y no es reparable → NO aprueba, escala al humano con razón documentada.

🚀Las 6 Mejoras 100x — Resumen Ejecutivo

100x #1
Output Contract Tipado

Antes: el output era "lo que saliera". Ahora: el OutputContract define EXACTAMENTE qué artefactos, qué formato, qué audience, qué requirements. Validado con Pydantic en runtime. Si el contrato dice artifacts: ["report.md", "tests.xml"], el sistema NO entrega si falta alguno.

100x #2
10 Checks Binarios Objetivos

Antes: el LLM decidía si "estaba bien". Ahora: 10 checks específicos, cada uno PASS o FAIL con issues listados. Si placeholders, FAIL. Si contradicciones, FAIL. Si formato mal, FAIL. Sin subjetividad.

100x #3
Hallucination Detection

借鉴 SelfCheckGPT: muestrea N=5 variantes de la misma respuesta, mide inconsistencia. Si >30% se contradicen, marca como sospechoso. Esto detecta cuando el modelo "inventa" contenido.

100x #4
Repair Automático (1 retry)

Si un check falla, el sistema intenta reparar 1 vez con el LLM antes de escalar. Solo si la reparación falla → escala al humano. Esto evita que errores triviales lleguen al usuario.

100x #5
Output Diff

Compara el goal inicial vs el output final. Calcula coverage_score (0-1) y lista gaps específicos. El usuario sabe EXACTAMENTE qué del goal original quedó cubierto y qué no.

100x #6
Audit Log Hash-Chained

借鉴 kbot-finance: cada output aprobado genera una entry inmutable con hash del anterior. verify_integrity() recorre toda la cadena y verifica que ningún hash fue alterado. Perfecto para auditoría.
