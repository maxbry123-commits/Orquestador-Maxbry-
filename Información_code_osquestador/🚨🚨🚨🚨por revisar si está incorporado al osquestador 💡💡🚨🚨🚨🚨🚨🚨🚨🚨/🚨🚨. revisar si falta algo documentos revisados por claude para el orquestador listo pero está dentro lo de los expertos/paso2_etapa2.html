🔍TAREA 1 — Investigación

Fuentes que借鉴 para mejorar el Execution Cognitive Fabric.

TDFlow (arXiv 2510.23761)
PaperStanford

Qué es

Framework que usa TDD como workflow agentic: propone, revisa y depura parches a escala de repositorio resolviendo tests escritos por humanos.

Qué借鉴

El flujo TDD obligatorio: test rojo → implementación verde → refactor. Sin test previo, no se escribe código de implementación.

Aplicación a MAXBRY

Tu Code Generator y Test Runner trabajan en pares TDD: el Test Runner escribe el test primero, Code Generator escribe lo mínimo para pasarlo.

DSPy (Stanford)
FrameworkStanford NLP

Qué es

Compilador que optimiza prompts automáticamente usando machine learning en vez de ajuste manual.

Qué借鉴

El concepto de compilador de prompts: el sistema evalúa outputs contra métricas y ajusta los prompts automáticamente.

Aplicación a MAXBRY

Tu Optimizer puede usar DSPy-style: si un experto tiene bajo rendimiento, ajusta su prompt automáticamente basándose en feedback.

OpenHands / Cursor Agent
FrameworkProduction

Qué es

Agentes de código que ejecutan en sandboxes Docker aislados, paralelizan con git worktrees, corren tests reales.

Qué借鉴

El patrón de sandbox seguro con Docker + git worktrees para paralelización sin conflictos.

Aplicación a MAXBRY

Tu Execution Fabric corre cada code-generator en un Docker container aislado con sus propios worktrees.

AG2 / AutoGen (Microsoft)
FrameworkMicrosoft

Qué es

Framework con patrón "group chat" donde múltiples agentes con roles distintos conversan para resolver tareas.

Qué借鉴

El patrón de roles tipados con speaking order configurable y termination conditions explícitas.

Aplicación a MAXBRY

Parallel Code Review (agent-skills)
Skill Pack

Qué es

Patrón de code review que lanza 5 sub-agentes en paralelo, cada uno con foco especializado (correctness, architecture, types, security, vision).

Qué借鉴

El patrón de 5-lens parallel review: 5 agentes analizan el código simultáneamente, luego se sintetiza.

Aplicación a MAXBRY

OI-MAS (arXiv 2601.04861)
Paper

Qué es

Multi-agent system con confidence-aware routing: cada experto declara su confidence y el sistema elige la mejor combinación.

Qué借鉴

El patrón de confidence-aware consensus: cada voto lleva su confidence, el sistema pondera.

Aplicación a MAXBRY

MEJORA #1
Execution como Pipeline Tipado

Cada stage del Execution tiene un contrato I/O estricto.借鉴 de AutoGen.

from typing import TypedDict

class ExecutionState(TypedDict):
    task_node: "TaskNode"
    code_artifacts: list["CodeArtifact"]
    test_results: list["TestResult"]
    validation_errors: list["ValidationError"]
    review_verdict: "ReviewVerdict | None"
    optimization_report: "OptimizationReport | None"
    consensus_votes: list["Vote"]
    retry_count: int
    status: Literal["running", "passed", "failed", "escalated"]


class ExecutionPipeline:
    """Pipeline tipado con stages secuenciales."""

    def __init__(self):
        self.stages = [
            CodeGenerator(),
            Validator(),
            TestRunner(),
            Repair(),       # solo si Validator/TestRunner falla
            Reviewer(),
            Optimizer(),    # opcional, si se pidió perf
            Consensus(),    # solo si consensus=true en Control Plane
            ArtifactBuilder(),
        ]

    async def execute(self, task: "TaskNode") -> "ExecutionResult":
        state = ExecutionState(task_node=task, status="running")
        for stage in self.stages:
            if not stage.should_run(state):
                continue
            state = await stage.run(state)
            if state.status == "escalated":
                break
        return state

TDD Obligatorio
class TDDPair:
    """Code Generator + Test Runner en pares TDD (借鉴 TDFlow)."""

    async def implement(self, task: "TaskNode") -> "CodeArtifact":
        # RED: escribir test que falle
        test = await self.test_runner.write_failing_test(task)
        result = await self.test_runner.run(test)
        assert result.status == "failed", "Test debe fallar antes de implementar"

        # GREEN: mínima implementación que pase el test
        code = await self.code_generator.write_minimal(task, test)
        result = await self.test_runner.run(test)
        while result.status != "passed":
            code = await self.code_generator.fix(code, result.errors)
            result = await self.test_runner.run(test)

        # REFACTOR: mejorar sin romper tests
        code = await self.code_generator.refactor(code)
        return code

Sandbox Seguro con Docker
class DockerSandbox:
    """Cada Code Generator corre en Docker aislado (借鉴 OpenHands)."""

    def __init__(self, image: str = "python:3.11-slim"):
        self._client = docker.from_env()
        self._image = image

    async def execute(self, code: str, tests: str) -> "TestResult":
        container = self._client.containers.run(
            self._image,
            command="bash -c 'python -m pytest'",
            volumes={"/tmp/code": {"bind": "/app", "mode": "ro"}},
            mem_limit="512m",
            cpu_quota=50000,
            network_disabled=True,  # sin red
            detach=True,
            remove=True,
        )
        result = container.wait()
        logs = container.logs().decode("utf-8")
        return TestResult(
            exit_code=result["StatusCode"],
            logs=logs,
            passed=result["StatusCode"] == 0,
        )

Repair con Backoff Exponencial
class RepairWithBackoff:
    """Retry inteligente con backoff exponencial."""

    MAX_RETRIES = 5

    async def repair(self, code: str, errors: list) -> str:
        for attempt in range(self.MAX_RETRIES):
            try:
                fixed = await self._apply_fix(code, errors)
                if await self._validate(fixed):
                    return fixed
            except Exception as e:
                errors = [str(e)]

            # Backoff exponencial: 1s, 2s, 4s, 8s, 16s
            await asyncio.sleep(2 ** attempt)

        raise RepairFailed(f"Could not repair after {self.MAX_RETRIES} attempts")

Consensus Configurable
class ConfigurableConsensus:
    """3 mayoría o 5 unanimidad según criticidad (借鉴 OI-MAS)."""

    async def vote(self, code: "CodeArtifact", strategy: str) -> "Verdict":
        if strategy == "majority_3":
            voters = ["code_reviewer_a", "code_reviewer_b", "code_reviewer_c"]
            threshold = 2  # 2 de 3
        elif strategy == "unanimity_5":
            voters = [f "code_reviewer_{chr(ord('a') + i)}" for i in range(5)]
            threshold = 5  # 5 de 5

        votes = await asyncio.gather(*[self._get_vote(v, code) for v in voters])
        approvals = sum(1 for v in votes if v.approved)
        return Verdict(
            approved=approvals >= threshold,
            votes=votes,
            strategy=strategy,
        )

class ArtifactBuilder:
    """Cada artefacto versionado con hash + autor + commit (借鉴 Git)."""

    def build(self, code: str, review: "ReviewVerdict") -> "Artifact":
        content_hash = hashlib.sha256(code.encode()).hexdigest()[:12]
        return Artifact(
            id=f"art-{content_hash}",
            content_hash=content_hash,
            author="execution-fabric",
            timestamp=datetime.utcnow().isoformat(),
            commit_message=self._generate_commit_message(review),
            parent_hash=self._get_previous_hash(),
            files=self._extract_files(code),
        )
